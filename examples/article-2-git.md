# Git 分支管理

Git 的分支（branch）是版本控制的核心概念之一。一个分支本质上是一个指向某个提交（commit）的轻量级指针，创建和切换分支几乎不消耗资源。

常用的分支模型是"功能分支"（feature branch）模型：主分支 main 保持稳定，任何新功能或修复都在独立分支上开发，完成后通过合并请求（pull request）或 git merge 合并回 main。

合并主要有两种方式：fast-forward（快进）和 three-way merge（三方合并）。当目标分支没有新的提交时，Git 直接移动指针，称为快进合并；当两边都有新提交时，Git 会创建一个新的合并提交，把两个分支的历史整合在一起。

当两个分支修改了同一文件的同一部分时，会产生冲突（conflict）。解决冲突需要手动编辑文件，保留想要的改动，然后 git add 标记为已解决并提交。

为了避免 main 分支被破坏，很多团队会要求：合并前通过自动化测试、至少一名成员代码审查（code review）、以及保持提交历史清晰。

一个常见的实践是"rebase 与 merge 的取舍"：rebase 让历史线性、干净，但会改写提交历史，不适合已经公开分享的分支；merge 保留完整历史，但可能产生较多合并提交。
